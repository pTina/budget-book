# 자산현황 요구사항 정의서

가계부 앱에 **자산** 영역을 추가한다. 사용자는 연금·주식·코인 등 직접 만든 카테고리로 원금을 기록하고, **월/년 추이**와 **세부내역**을 본다.

화면 기준은 `docs/asset-mockup.html`을 따른다. 공통 토큰·팝업·접근성은 기존 `docs/요구사항정의서.md`와 `docs/frontend-design.md`를 따른다.

이 문서는 자산 기능만 다룬다. 가계부(지출·예산·통계) 요구사항은 기존 정의서를 유지한다.

---

## 1. 목표

- 캘린더 없이 **월·년 단위**로 자산 규모가 어떻게 변했는지 본다.
- 같은 기간의 **보유 / 매수 / 매도** 기록을 세부내역에서 확인·수정한다.
- **투자 원금**과 **평가금액**을 따로 적고, 수익률(%)을 함께 본다.
- 시세 연동은 하지 않는다. 평가금액은 사용자가 직접 입력한다.

---

## 2. 범위

### 2.1 포함

- 앱 상단 `가계부 | 자산` 영역 전환
- 자산 카테고리 CRUD (사용자 지정, 시드: 연금 / 주식 / 코인)
- 자산 기록 CRUD: 구분 `매수 | 매도 | 보유`
- 기간 단위 `월 | 년` + 이전/다음 이동
- 추이: 기간 말 **평가금액**, 원금·평가손익·수익률, 대비 증감, 막대 차트, 카테고리별 평가/원금
- 세부내역: 카테고리 필터, 날짜(월) 또는 월(년) 그룹 목록
- PC 좌우 분할, MO 추이/세부내역 탭

### 2.2 제외

- 실시간 시세, 증권사·은행 연동, CSV 가져오기
- 수량(주/코인 개수), 단가, 환율
- 가계부 지출·예산과의 자동 연결
- 자산 목표액, 리밸런싱, 알림

## 3. 핵심 개념

| 용어 | 의미 |
|---|---|
| 보유 | 특정 날짜의 잔고. **투자 원금**과 **평가금액**을 따로 둘 수 있다. |
| 매수 | 그 날짜에 넣은 원금 (+). 평가금액은 선택. |
| 매도 | 그 날짜에 뺀 원금 (−). 평가금액 없음. |
| 원금 | `보유 원금 합 + 매수 원금 합 − 매도 원금 합` (기간 말까지). |
| 평가금액 | `보유/매수 평가(없으면 원금) 합 − 매도 원금 합`. 차트·총액의 기본값. |
| 평가손익 | `평가금액 − 원금`. |
| 수익률 | 원금이 1 이상일 때 `(평가 − 원금) / 원금`, 소수 첫째 자리 `%`. `+`는 `--color-rate-plus` `#C44545`, `−`는 `--color-rate-minus` `#3B6FD8`, **0%는 색을 바꾸지 않는다**. |

같은 종목에 `보유`와 `매수`를 같이 넣으면 **둘 다 합산**된다. 기초 잔고는 `보유`, 이후 변동은 `매수`/`매도`로 기록하는 것을 기본 사용법으로 안내한다.

미래 날짜 기록은 허용한다. 추이·합계는 **선택 기간의 말일까지** 포함된 기록만 쓴다. (월 보기 2026.09 → 2026-09-30까지, 년 보기 2026 → 2026-12-31까지. 올해·당월은 말일 기준이며 오늘로 자르지 않는다.)

## 4. 데이터 모델

기존 `StorageAdapter`에 자산 메서드를 추가한다. ID·날짜·금액 규칙(UUID, `YYYY-MM-DD`, 정수 원, `undefined` 제거)은 가계부와 동일하다.

```ts
type AssetType = 'buy' | 'sell' | 'hold';   // 매수 | 매도 | 보유
type PeriodUnit = 'month' | 'year';

interface AssetCategory {
  id: ID;
  name: string;          // 1~10자, 자산 카테고리 내 중복 불가
  color: string;         // HEX, 가계부 카테고리 팔레트 재사용
  order: number;
}

interface AssetEntry {
  id: ID;
  date: DateStr;
  type: AssetType;
  amount: number;        // 투자 원금, 원 단위 정수, 1 이상
  value?: number;        // 평가금액. 없거나 원금과 같으면 생략. 매도에는 저장하지 않음
  categoryId: ID | null; // null = 미분류
  title: string;         // 1~30자 (종목·상품명)
  memo?: string;         // 최대 100자
  createdAt: string;
  updatedAt: string;
}
```

### 4.1 시드 카테고리

| 이름 | 색상 |
|---|---|
| 연금 | `#C0E8DD` |
| 주식 | `#A3C6EB` |
| 코인 | `#F7E2B8` |

- `미분류`는 저장하지 않는 표시용 가상 카테고리 (색상 `#D4D8DE`).
- 가계부 카테고리와 **별도 목록**이다.

### 4.2 저장

| 키 / 컬렉션 | 내용 |
|---|---|
| `ledger:asset-categories` | AssetCategory[] |
| `ledger:asset-entries` | AssetEntry[] |

Firestore (2단계): `users/{uid}/assetCategories/{id}`, `users/{uid}/assetEntries/{id}` (`date` 인덱스).

### 4.3 어댑터 추가

```ts
getAssetCategories(): Promise<AssetCategory[]>;
saveAssetCategory(input: AssetCategoryInput, id?: string): Promise<AssetCategory>;
deleteAssetCategory(id: string): Promise<void>;  // 연결 기록은 categoryId = null

getAssetEntries(): Promise<AssetEntry[]>;        // 개인 데이터라 전체 조회 후 클라이언트 집계
createAssetEntry(input: AssetEntryInput): Promise<AssetEntry>;
updateAssetEntry(id: string, input: Partial<AssetEntryInput>): Promise<AssetEntry>;
deleteAssetEntry(id: string): Promise<void>;
```

## 5. 비즈니스 규칙

### 5.1 잔고 계산

`asOf`(포함) 기준:

```
원금(asOf)   = Σ hold.amount + Σ buy.amount − Σ sell.amount   (date ≤ asOf)
평가(asOf)   = Σ hold.(value ?? amount) + Σ buy.(value ?? amount) − Σ sell.amount
수익률       = 원금 > 0 ? (평가 − 원금) / 원금 : 표시 안 함
```

카테고리별도 동일하되 `categoryId`로 필터한다. 미분류는 별도 행으로 표시한다.

- 추이 큰 숫자·차트·카테고리 오른쪽 금액: **평가**
- 카테고리 이름 아래: **원금**, 오른쪽 아래: **수익률 %**
- 금액 표시: 천 단위 콤마 + `원`, `tabular-nums`
- 매도 목록: `−` 접두. 보유 목록 메인은 평가(있으면), 매수는 `+` 원금
- 평가가 원금과 다를 때만 목록에 평가와 수익률을 덧붙인다. 사이 **가운뎃점(`·`)은 쓰지 않는다**. 예: `평가 1,350,000원 +12.5%`, 보유는 `평가 +6.9%`
- 수익률 색: `+` → `--color-rate-plus` `#C44545`, `−` → `--color-rate-minus` `#3B6FD8`, `0%` → 부모 텍스트색 유지
- 음수 원금/평가도 그대로 표시한다

### 5.2 월 보기 추이

- 선택 월 `YYYY-MM`의 **월말 평가금액**을 총액으로 표시한다.
- 대비: 이번 달 말 평가 − 전월 말 평가.
- 그 아래 `원금 N원 · 평가손익 +M원 (+P%)`.
- 차트: **선택 월 포함 최근 6개월** 월말 **평가** 막대. 없는 달은 0. 선택 월만 강조.
- 카테고리: 평가 내림차순, 원금·수익률 병기. 비율 바는 `해당 카테고리 평가 / 총 평가`.

### 5.3 년 보기 추이

- 선택 연 **연말 평가금액**. 대비는 전년 말 평가.
- 차트: **최근 5년** 연말 평가. 카테고리 규칙은 월 보기와 같다.

### 5.4 세부내역

- 월: 선택 월의 기록만. **날짜 내림차순**, 같은 날은 `9월 18일` 헤더 아래 묶는다.
- 년: 선택 연의 기록만. **월 내림차순**, `9월` 헤더 아래 묶고 항목 메타에 `카테고리 · 9.18`처럼 일을 붙인다.
- 필터 칩: `전체` + 카테고리 이름. 단일 선택. 미분류가 있으면 `미분류` 칩을 뒤에 둔다.
- 항목: 제목, 구분 뱃지, 카테고리, **원금**. 평가가 원금과 다르면 평가액과 수익률(%)을 오른쪽에 표시한다. 구분은 공백이며 가운뎃점은 쓰지 않는다.
- **메모가 있을 때만** 제목·메타 아래에 한 줄로 표시한다. 없으면 자리를 남기지 않는다.
- 항목 클릭 → 수정 팝업.
- 빈 상태: `이 기간에 기록이 없어요.`

### 5.5 카테고리

- 삭제 시 확인. 연결 기록은 `categoryId = null`.
- 이름 중복 불가. 순서 `order`. MVP 드래그 정렬 없음.
- 폼의 `+ 추가`는 인라인 생성 후 자동 선택. (가계부 카테고리와 동일 패턴)

### 5.6 입력 제한

- 금액(원금·평가): 숫자만, 입력 중 콤마, 1 ~ 99,999,999
- 평가금액은 매수·보유만. 비우면 원금과 같게 저장. 매도 폼에서는 숨김.
- 제목 1~30자, 메모 최대 100자
- 날짜 필수
- 구분·카테고리 필수 (카테고리가 0개여도 `+ 추가`로 만들 수 있음. 카테고리 없이 저장하면 미분류)

## 6. 화면

브레이크포인트는 가계부와 같다. MO ≤ 767px, PC ≥ 768px.

### 6.1 공통 헤더 (자산 영역)

```
가계부(PC만)   [가계부][자산]   ⚙
[월][년]   ‹ 2026.09 ›     ← 년 단위면 ‹ 2026 ›
```

- `가계부` 탭 → 기존 캘린더/통계/세부내역.
- `자산` 탭 → 이 문서의 화면. 설정 아이콘은 기존 설정 팝업(예산·지출 카테고리 등)을 연다. 자산 카테고리 관리는 자산 기록 폼의 `+ 추가`와, 필요 시 설정에 `자산` 탭을 추가해도 된다. **MVP는 폼 `+ 추가` + 수정 팝업에서 카테고리 칩 변경으로 충분**하다. 자산 카테고리 삭제·이름 변경 UI는 설정 팝업 `자산` 탭으로 둔다.

### 6.2 MO

```
[추이][세부내역]
(선택된 패널)
[ + 기록 ]   ← FAB, 높이 44px
```

- 추이: **평가금액** → 대비 → 원금·평가손익·수익률 → 차트 → 안내 → 카테고리(평가 + 원금 + %). 수익률은 `+` 빨강, `−` 파랑, 0%는 기본색.
- 세부내역: 필터 칩 → 그룹 목록. 메모가 있는 항목만 메모 줄을 보여 준다.
- 카테고리 목록이 길면 **페이지(패널) 스크롤**. (MO는 총액·차트와 함께 스크롤)

### 6.3 PC

우측 세부내역 패널 **380px**. 좌측 추이가 나머지.

```
┌─ 추이 ─────────────────────┬─ 세부내역 380px ──┐
│ 9월 평가금액               │ 세부내역    [+ 기록]│
│ 13,210,000원               │ [전체][연금]…      │
│ 전월 대비 +1,520,000원      │ 9월 18일           │
│ 원금 12,480,000 · +5.8%    │ 삼성전자 매수  +…   │
│  [막대 6개]  │ 연금 8,000,000│                    │
│              │ 주식 3,200,000│                    │
│              │ 코인 1,280,000│                    │
└──────────────┴─────────────┴────────────────────┘
```

- 총액·대비는 좌측 상단 한 줄 블록.
- 그 아래 **차트 | 카테고리** 가로 배치. PC에서 차트 열이 카테고리보다 넓고, 막대는 열 너비에 맞춰 퍼진다. MO는 내용 너비.
- 카테고리가 늘어나면 **카테고리 열만 스크롤**. 총액·차트는 고정.
- 세부내역 헤더·필터는 고정, 목록만 스크롤.
- FAB 숨김. `+ 기록`은 우측 헤더 버튼.

### 6.4 자산 기록 팝업 (PC·MO 공통 레이어)

| 필드 | 형태 | 필수 |
|---|---|---|
| 구분 | 세그먼트 `매수 | 매도 | 보유` | ✔ |
| 카테고리 | 칩 단일 선택 + `+ 추가` | 있으면 ✔ |
| 투자 원금 | 숫자 | ✔ |
| 평가금액 | 숫자. 매도 시 숨김. 비우면 원금과 같음 | |
| 날짜 | date (기본: 오늘, 수정 시 기존값) | ✔ |
| 제목(메모 위 내용) | 텍스트. 목업의 메모 자리에 종목명을 둔다. 라벨은 `내용` | ✔ |
| 메모 | 텍스트 | |

- 하단 `취소` / `저장`, 수정 시 좌측 `삭제`.
- 삭제 확인: `이 기록을 삭제할까요?`
- 팝업 규칙은 가계부와 동일 (딤, ESC, 포커스 트랩, z-index 스택).

## 7. 라우팅 · 상태

| 경로 | 화면 |
|---|---|
| `/assets/:period` | 자산. `period`가 `YYYY-MM`이면 월, `YYYY`이면 년 |

- `/assets` → 현재 월 `/assets/YYYY-MM`으로 리다이렉트.
- 가계부 경로는 기존 유지.
- 영역 전환 시 마지막으로 보던 가계부 월 / 자산 기간을 각각 기억한다.

### Query

| queryKey | 내용 |
|---|---|
| `['asset-categories']` | 자산 카테고리 |
| `['asset-entries']` | 전체 자산 기록 |

추이·필터는 `lib/assetStats.ts` 순수 함수로 계산한다.

### UI (Zustand)

```ts
assetPeriodUnit: PeriodUnit;
assetView: 'trend' | 'details';   // MO 탭. PC는 둘 다 표시
```

- `assetView`는 persist. PC에서는 무시.

## 9. 완료 기준

- [ ] `가계부 | 자산`으로 영역이 나뉘고, 자산에는 캘린더 그리드가 없다
- [ ] 월/년 전환과 ‹ › 이동이 총액·차트·세부내역에 같이 반영된다
- [ ] 월 추이는 최근 6개월 월말 **평가**, 년 추이는 최근 5년 연말 평가를 보여 준다
- [ ] 원금과 평가금액을 따로 저장하고, 평가손익·수익률(%)이 맞다
- [ ] 세부내역에 메모가 있을 때만 목록에 표시된다
- [ ] 수익률은 `+` `--color-rate-plus`, `−` `--color-rate-minus`, 0%는 색 변경 없음. 평가와 수익률 사이 가운뎃점이 없다
- [ ] 매도는 평가금액 입력란이 없고, 비운 평가는 원금과 같게 저장된다
- [ ] 매수/매도/보유 등록·수정·삭제가 추이와 목록에 즉시 반영된다
