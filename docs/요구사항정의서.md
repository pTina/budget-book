# 가계부 서비스 요구사항 정의서

일별 지출을 기록하고 월별 소비를 확인하는 반응형(PC/MO) 가계부 웹 서비스.
기존 다이어리 서비스(https://ptina.github.io/daily-diary/)의 레이아웃을 기반으로, 우측 할일 목록 대신 지출 목록을 표시한다.
화면 기준은 함께 전달하는 목업 `household-ledger-mockup.html`을 따른다.

## 2. 범위

### 2.1 MVP 포함
- 월간 캘린더 + 일별 지출 목록
- 지출 등록 / 수정 / 삭제 (지출만 기록, 수입 없음)
- 월 예산 설정 및 사용률·잔여액 표시 (on/off 가능)
- 카테고리별 월간 통계 (도넛 차트 + 순위 리스트)
- 카테고리 관리 (기본 제공 + 추가 / 수정 / 삭제)
- 결제수단 관리 (사용자 직접 등록 / 수정 / 삭제)
- 반복 지출 (구독·고정비), 등록 시 카테고리·결제수단 지정

### 2.2 MVP 제외
- 로그인 / 계정 (단일 사용자)
- 수입 기록
- 알림
- 데이터 내보내기

## 3. 데이터 저장 전략

### 3.1 2단계 어댑터 패턴
- **1단계:** localStorage 어댑터
- **2단계:** Firebase Firestore 어댑터로 교체 (기기 간 동기화)
- 어댑터 파일만 교체하면 되도록 인터페이스를 고정한다.
- **모든 어댑터 함수는 처음부터 `async`로 작성**한다. (전환 시 호출부 수정 방지)

```ts
// src/api/adapter.ts
export interface StorageAdapter {
  getExpenses(month: string): Promise<Expense[]>;          // month: 'YYYY-MM'
  createExpense(input: ExpenseInput): Promise<Expense>;
  updateExpense(id: string, input: Partial<ExpenseInput>): Promise<Expense>;
  deleteExpense(id: string): Promise<void>;

  getCategories(): Promise<Category[]>;
  saveCategory(input: CategoryInput, id?: string): Promise<Category>;
  deleteCategory(id: string): Promise<void>;               // 연결 지출은 미분류로 이동

  getPayments(): Promise<Payment[]>;
  savePayment(input: PaymentInput, id?: string): Promise<Payment>;
  deletePayment(id: string): Promise<void>;                // 연결 지출은 미분류로 이동

  getRecurrings(): Promise<Recurring[]>;
  saveRecurring(input: RecurringInput, id?: string): Promise<Recurring>;
  deleteRecurring(id: string, scope: EditScope, fromDate?: string): Promise<void>;
  saveRecurringException(input: RecurringException): Promise<void>;

  getBudget(month: string): Promise<Budget | null>;
  saveBudget(input: Budget): Promise<Budget>;

  getSettings(): Promise<Settings>;
  saveSettings(input: Partial<Settings>): Promise<Settings>;
}
```

### 3.2 localStorage 키
| 키 | 내용 |
|---|---|
| `ledger:expenses` | Expense[] |
| `ledger:categories` | Category[] |
| `ledger:payments` | Payment[] |
| `ledger:recurrings` | Recurring[] |
| `ledger:recurring-exceptions` | RecurringException[] |
| `ledger:budgets` | Budget[] |
| `ledger:settings` | Settings |

- 모든 읽기/쓰기는 try/catch로 감싸고, 값이 없거나 파싱 실패 시 기본값을 반환한다.
- 최초 실행 시 기본 카테고리와 기본 설정을 시드로 저장한다.

### 3.3 Firebase 전환 대비 규칙 (1단계부터 지킬 것)
Firebase 전환 시 **`api/index.ts`의 어댑터 선택만 바꾸면 동작**해야 한다.

**어댑터 선택**
```ts
// src/api/index.ts
import { localAdapter } from './localAdapter';
import { firebaseAdapter } from './firebaseAdapter';

export const api: StorageAdapter =
  import.meta.env.VITE_STORAGE === 'firebase' ? firebaseAdapter : localAdapter;
```
- 컴포넌트·훅은 `api`만 import하고, localStorage나 Firebase SDK를 직접 호출하지 않는다.
- Firebase 설정값은 `.env`(`VITE_FIREBASE_API_KEY` 등)로 관리하고 저장소에 커밋하지 않는다.

**데이터 형식 통일**
- ID는 클라이언트에서 `crypto.randomUUID()`로 생성 (Firestore 자동 ID 사용 안 함)
- 날짜는 `'YYYY-MM-DD'` 문자열, `createdAt/updatedAt`은 ISO 문자열로 저장 (Firestore Timestamp 사용 안 함)
- `undefined` 필드는 저장 전에 제거 (Firestore는 `undefined` 저장 불가)
- 금액은 정수(number)로만 저장

**어댑터 책임 범위**
- 어댑터는 CRUD와 연쇄 처리만 담당하고, 반복 전개·예산·통계 계산은 `lib/`에서 처리한다.
- 여러 문서를 함께 바꾸는 작업은 어댑터 안에서 한 번에 처리한다. (Firebase는 `writeBatch` 사용)
  - 카테고리/결제수단 삭제 → 연결 지출·반복 지출 미분류 처리
  - 반복 지출 `이후 전체` 수정/삭제 → 기존 규칙 종료 + 새 규칙 생성
- 월별 지출 조회는 날짜 범위 조건(`date >= 'YYYY-MM-01'` and `date < 다음 달 1일`)으로 구현한다. (문자열 정렬 가능 형식이므로 Firestore 범위 쿼리와 동일하게 동작)

**Firestore 컬렉션 구조 (2단계)**
| 경로 | 문서 ID | 내용 |
|---|---|---|
| `users/{uid}/expenses/{id}` | UUID | Expense (`date` 필드 인덱스) |
| `users/{uid}/categories/{id}` | UUID | Category |
| `users/{uid}/payments/{id}` | UUID | Payment |
| `users/{uid}/recurrings/{id}` | UUID | Recurring |
| `users/{uid}/recurringExceptions/{recurringId}_{date}` | 조합 키 | RecurringException |
| `users/{uid}/budgets/{YYYY-MM}` | 월 | Budget |
| `users/{uid}/settings/app` | 고정 | Settings |

- 단일 사용자 서비스지만 보안 규칙 적용을 위해 2단계에서 **Firebase 익명 인증**으로 `uid`를 발급한다.
- 보안 규칙: `request.auth.uid == uid`인 경우만 `users/{uid}/**` 읽기/쓰기 허용

**전환 준비물**
- `firebaseAdapter.ts`는 1단계에서 인터페이스만 구현한 빈 파일(`throw new Error('not implemented')`)로 둔다.
- 어댑터 계약 테스트: 동일한 테스트 스위트를 localAdapter와 firebaseAdapter(에뮬레이터)에 모두 실행할 수 있게 작성한다.
- 2단계에서 localStorage 데이터를 Firestore로 옮기는 1회성 `migrateLocalToFirebase()` 함수를 제공한다.

## 4. 데이터 모델

```ts
type ID = string;                // crypto.randomUUID()
type DateStr = string;           // 'YYYY-MM-DD'
type MonthStr = string;          // 'YYYY-MM'

interface Expense {
  id: ID;
  date: DateStr;
  amount: number;                // 원 단위 정수, 1 이상
  title: string;                 // 내용, 1~30자
  categoryId: ID | null;         // null = 미분류
  paymentId: ID | null;          // null = 미분류
  memo?: string;                 // 최대 100자
  recurringId?: ID;              // 반복 지출에서 생성된 경우
  createdAt: string;
  updatedAt: string;
}

interface Category {
  id: ID;
  name: string;                  // 1~10자, 중복 불가
  color: string;                 // HEX
  order: number;
  isDefault: boolean;            // 기본 제공 여부 (기본 제공도 수정/삭제 가능)
}

interface Payment {
  id: ID;
  name: string;                  // 1~15자, 중복 불가 (예: 신한카드, 현금)
  order: number;
}

type Cycle = 'monthly' | 'weekly' | 'yearly';

interface Recurring {
  id: ID;
  title: string;
  amount: number;
  categoryId: ID | null;         // 등록 시 사용자가 지정
  paymentId: ID | null;          // 등록 시 사용자가 지정
  cycle: Cycle;
  day: number;                   // monthly: 1~31 (32 = 말일) / weekly: 0~6(일~토) / yearly: 1~31
  month?: number;                // yearly 전용, 1~12
  startDate: DateStr;
  endDate?: DateStr;
  memo?: string;
}

interface RecurringException {
  recurringId: ID;
  date: DateStr;                 // 해당 회차 날짜
  type: 'skip' | 'override';     // skip = 이번 회차 삭제, override = 이번 회차만 수정
  override?: Partial<Pick<Expense, 'amount' | 'title' | 'categoryId' | 'paymentId' | 'memo'>>;
}

type EditScope = 'this' | 'following';   // 이번만 / 이후 전체

interface Budget {
  month: MonthStr;
  amount: number;
}

interface Settings {
  budgetEnabled: boolean;        // 예산 on/off (기본 true)
  defaultBudget: number | null;  // '다음 달에도 같은 예산 적용' 시 사용
  applyBudgetToNextMonths: boolean;
}
```

### 4.1 기본 카테고리 (시드)
| 이름 | 색상 |
|---|---|
| 식비 | `#F5CBA7` |
| 카페 | `#E6D3B3` |
| 교통 | `#A3C6EB` |
| 쇼핑 | `#F2B8C6` |
| 생활 | `#C0E8DD` |
| 구독 | `#CFC6F0` |
| 문화 | `#F3E3A1` |

- 카테고리 추가 시 선택 가능한 파스텔 팔레트 12색을 제공한다.
- `미분류`는 저장 데이터가 아닌 표시용 가상 카테고리 (색상 `#D4D8DE`).

## 5. 비즈니스 규칙

### 5.1 반복 지출
- 반복 규칙(`Recurring`)만 저장하고, 조회 시 **해당 월 범위로 클라이언트에서 전개**해 가상 지출 항목을 만든다.
- 전개 결과는 실제 `Expense`와 합쳐 동일한 목록/합계/통계에 사용한다.
- `RecurringException`을 반영한다. (`skip`은 제외, `override`는 값 덮어쓰기)
- 월 결제일이 해당 월에 없으면(예: 31일, 2월) 그 달의 말일로 처리한다.
- **오늘 이후 회차는 `예정` 상태**로 표시한다. (목록에서 흐리게 + `예정` 태그, 캘린더 합계는 흐린 색)
- 수정/삭제 시 범위 선택 다이얼로그를 띄운다.
  - `이번만`: 해당 회차에 exception 저장
  - `이후 전체`: 기존 규칙의 `endDate`를 전날로 끊고, 변경된 값으로 새 규칙 생성 (삭제면 끊기만 함)
- 목록에서 반복 지출 항목은 반복 아이콘을 표시한다.

### 5.2 예산
- 사용액 = 해당 월 **오늘까지의 지출 합계** (예정 반복 지출 제외)
- 사용률 = 사용액 / 예산, 잔여액 = 예산 − 사용액 (음수 가능, 음수면 `초과 N원`으로 표시)
- 사용률 90% 이상이면 진행률 바를 경고색으로 표시한다.
- `budgetEnabled = false`일 때
  - 패널(MO는 상단)의 예산 영역 숨김
  - 통계의 `남은 예산` 항목 숨김
  - 설정의 예산 입력란 비활성화
  - **입력된 예산 값은 삭제하지 않고 보관** (다시 켜면 복원)
- `다음 달에도 같은 예산 적용`이 켜져 있으면 예산이 없는 월은 `defaultBudget`을 사용한다.
- 예산 미설정 + on 상태면 예산 영역에 `예산 설정하기` 안내를 표시한다.

### 5.3 카테고리 / 결제수단
- 삭제 시 확인 다이얼로그 표시, 연결된 지출·반복 지출은 `categoryId/paymentId = null`(미분류)로 변경
- 이름 중복 불가, 순서는 `order` 기준 (MVP는 드래그 정렬 제외)
- 결제수단이 하나도 없으면 지출 등록 폼에서 결제수단 선택은 선택사항으로 처리

### 5.4 금액 표기
- 천 단위 콤마 + `원`
- MO 캘린더 셀은 축약 표기: 10,000원 이상 `1.2만`, 미만은 콤마 표기
- 금액 입력은 숫자만 허용, 입력 중 실시간 콤마 포맷, 최대 99,999,999원

## 6. 화면 설계

### 6.1 브레이크포인트
| 구분 | 폭 | 레이아웃 |
|---|---|---|
| MO | ≤ 767px | 캘린더 단독 + 날짜 탭 시 레이어 팝업 |
| PC | ≥ 768px | 캘린더 + 우측 패널(360px) |

### 6.2 공통 헤더
- 서비스명(PC만) / 월 이동(‹ YYYY.MM ›) / `오늘` 버튼(PC만) / 보기 전환 세그먼트 `캘린더 | 통계` / 설정 아이콘
- MO는 세그먼트를 두 번째 줄 전체 폭으로 배치

### 6.3 메인 – 캘린더 (PC)
```
┌─────────────────────────────────────────────────┐
│ 가계부 │ ‹ 2026.09 › [오늘] │ [캘린더][통계] │ ⚙ │
├──────────────────────────┬──────────────────────┤
│ 월간 캘린더 (7열)           │ 9월 예산        예산 수정│
│  · 셀: 날짜 + 카테고리 점   │ 687,000원 / 1,000,000원│
│        + 일 합계(우하단)    │ ▓▓▓▓▓▓░░░            │
│  · 오늘: 날짜 원형 강조      │ 69% 사용   남은 예산 …   │
│  · 선택: 셀 배경 + 테두리    ├──────────────────────┤
│  · 일요일: 날짜 빨간색       │ 9월 21일 (월)  25,000원│
│                          │ ▍점심 김치찌개  12,000원 │
│                          │   식비 / 신한카드        │
│                          │ ▍넷플릭스 ↻ 예정 17,000원│
```

- 셀 최소 높이 104px, 카테고리 점은 최대 4개

- 항목 클릭 → 지출 수정 팝업
- 빈 상태: `이 날은 지출이 없어요. 지출 추가로 기록을 남겨보세요.`

### 6.6 통계
```
‹ 2026.09 ›
  ( 도넛 차트 )      가장 많이 쓴 곳  식비
   9월 총 지출       하루 평균  31,227원
   687,000원        남은 예산  313,000원   ← 예산 off면 숨김
──────────────────────────────────────
▍식비  ████████████   320,000원  47%
▍교통  █████          150,000원  22%
```
- 기준: 선택 월, 오늘까지의 지출 (지난 달은 월 전체)
- 하루 평균 = 총 지출 / 경과 일수 (지난 달은 해당 월 일수)
- 금액 내림차순, 지출 0원 카테고리는 제외
- MO는 도넛과 요약을 세로 배치하고 비율(%) 열은 숨김
- 해당 월 지출이 없으면 빈 상태 표시

### 6.7 지출 등록/수정 팝업 (PC·MO 공통 레이어 팝업)
| 필드 | 형태 | 필수 |
|---|---|---|
| 금액 | 대형 숫자 입력 (최상단, 자동 포커스) | ✔ |
| 내용 | 텍스트 | ✔ |
| 날짜 | date (기본값: 선택된 날짜) | ✔ |
| 카테고리 | 칩 단일 선택 + `+ 추가` 칩 | ✔ |
| 결제수단 | 칩 단일 선택 + `+ 추가` 칩 | 결제수단 있을 때 ✔ |
| 반복 지출 | 토글 → on 시 주기 / 결제일 / 종료일(선택) 노출 | |
| 메모 | 텍스트 | |

- 하단: `취소` / `저장` (수정 모드는 좌측에 `삭제` 추가)
- `+ 추가` 칩은 인라인 입력으로 바로 생성 후 자동 선택
- 반복 지출 토글 on 상태로 저장하면 `Recurring` 생성 (지출이 아닌 규칙으로 저장)
- 반복 지출 회차를 수정/삭제하면 범위 선택 다이얼로그(`이번만` / `이후 전체`) 표시
- 유효성 오류는 필드 하단에 문구로 표시 (예: `금액을 입력하세요`)

### 6.8 설정 팝업 (탭 구성)
| 탭 | 내용 |
|---|---|
| 예산 | `예산 사용` 토글(최상단) / 월 예산 입력 / `다음 달에도 같은 예산 적용` 토글 / 저장 |
| 카테고리 | 색상 + 이름 목록, 수정 / 삭제, `+ 카테고리 추가` (이름 + 팔레트 색상 선택) |
| 결제수단 | 이름 목록, 수정 / 삭제, `+ 결제수단 추가` |
| 반복 지출 | 제목 / `주기 결제일 / 카테고리 / 결제수단` / 금액, 수정, `+ 반복 지출 추가`(지출 팝업을 반복 on 상태로 열기) |

- 각 탭 상단에 짧은 안내 문구 표시 (목업 참고)
- 패널의 `예산 수정` 클릭 시 설정 팝업의 예산 탭으로 바로 열기

### 6.9 확인 다이얼로그
- 삭제 확인: `이 지출을 삭제할까요?` / `취소`, `삭제`
- 반복 범위 선택: `이번만` / `이후 전체` / `취소`
- 카테고리·결제수단 삭제: `연결된 지출은 미분류로 옮겨져요.` 안내 포함

### 6.10 팝업 공통 규칙
- PC·MO 모두 **레이어 팝업** (바텀시트·전체화면 사용 안 함)
- 딤 클릭, ESC, 닫기 버튼으로 닫기
- 열릴 때 첫 입력 요소로 포커스 이동, 닫히면 트리거 요소로 포커스 복귀, 포커스 트랩 적용
- 팝업이 열려 있는 동안 body 스크롤 잠금

## 8. 상태 관리

### 8.1 TanStack Query (서버 상태)
| queryKey | 내용 |
|---|---|
| `['expenses', month]` | 월별 실제 지출 |
| `['recurrings']` | 반복 규칙 |
| `['recurring-exceptions']` | 반복 예외 |
| `['categories']` | 카테고리 |
| `['payments']` | 결제수단 |
| `['budget', month]` | 월 예산 |
| `['settings']` | 설정 |

- 월별 표시 데이터는 `useMonthExpenses(month)` 훅에서 실제 지출 + 반복 전개 결과를 합쳐 반환 (`select` 또는 `useMemo`)
- mutation 성공 시 관련 키 invalidate, 지출 등록/수정/삭제는 낙관적 업데이트 적용
- 인접 월 이동 대비 이전/다음 달 prefetch

## 11. 접근성
- 캘린더 셀은 `button`, `aria-label`에 `9월 21일 25,000원` 형태로 날짜와 합계 제공
- 세그먼트·설정 탭은 `role="tablist" / "tab"` + `aria-selected`

- 칩 선택은 `aria-pressed`
- 팝업은 `role="dialog"` + `aria-modal="true"` + `aria-labelledby`
- 모든 인터랙션 요소에 `focus-visible` 스타일 제공, 터치 영역 최소 44px

## 12. 코드 컨벤션
- 컴포넌트는 함수형 + named export, 파일명 PascalCase
- 비즈니스 로직(반복 전개, 예산·통계 계산)은 `lib/`의 순수 함수로 분리하고 단위 테스트 작성 (Vitest)
- 스타일은 Tailwind 유틸리티 우선, 별도 CSS 작성 시 `{}` 안의 선언은 1줄로 작성
- HTML/JSX 들여쓰기는 공백 2칸
- 매직 넘버 대신 상수 사용 (`BREAKPOINT_MO = 767`, `BUDGET_WARN_RATE = 0.9` 등)
